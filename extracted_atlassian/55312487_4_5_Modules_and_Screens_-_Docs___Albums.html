1. Executive Summary

EZBuild currently has an Albums capability inside Projects, but it is primarily a visual container for files and does not yet provide a complete document-management system.

This PRD defines a new Albums & Files foundation for EZBuild.

The system will operate at three levels:

  1. Lead level — files and albums related to a lead before conversion.

  2. Project level — all documents and media related to a project.

  3. Global level — a company-wide document center allowing authorized users to find files across all Leads and Projects.

The system will combine the simplicity of an album/gallery experience with the operational capabilities expected from construction document-management systems.

The goal is not to copy enterprise construction software.

EZBuild should take the proven industry concepts and make them significantly easier for SMB contractors.

2. Product Principle

EZBuild should organize documents around the way contractors work, not around the way file systems work.

The contractor should not have to become a document administrator.

EZBuild should automatically connect files to:

  • Lead

  • Project

  • Customer

  • Proposal & Estimate

  • Contract

  • Change Request

  • Invoice

  • Milestone

  • Subcontractor

  • Project type

  • Photos / portfolio

while still allowing the user to create their own organization.

3. Industry-Informed Design Principles

Construction platforms commonly use:

  • Project-specific document repositories

  • Company/global document repositories

  • Folder and subfolder structures

  • Role/company/user permissions

  • Permission inheritance

  • Version/revision management

  • Activity history

  • File sharing

  • Bulk operations

  • Project templates

  • Links between documents and project entities

Buildertrend, for example, supports job-specific and global files, folders, permissions, mass actions, versions, sharing and annotations.

Procore provides centralized project/company document repositories, folder permissions, revisions and activity tracking.

Autodesk Build uses standardized project folder structures and role-based permission templates that can be copied into new projects.

EZBuild should adopt these proven concepts but expose them through a much simpler UX.

59. Security Rules

  1. Users can only see files they have access to.

  2. Search must respect permissions.

  3. Smart Albums must respect permissions.

  4. Download must respect permissions.

  5. Share must respect permissions.

  6. Child permissions cannot bypass Project access.

  7. Permission changes must be audited.

  8. Deleted files must not remain accessible through old links.

  9. Customer access must never expose internal-only documents.

  10. Subcontractors must not automatically receive access to internal financial information.

No unnecessary duplication

One file, many views.

Visual where useful

Photos and albums should feel visual.

Operational where necessary

Documents should feel structured and searchable.
