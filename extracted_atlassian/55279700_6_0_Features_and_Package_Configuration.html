Feature and package configuration

·      Feature configuration – Feature or system functionality that should be enabled / disabled for user as part of his package definition.

·      Feature enabled should be fully functional for the user.

·      Feature disabled should have 2 options which are defined per feature (feature static configuration, not dynamic) – Feature can be disabled but visible to the customer (greyed out / marked as premium feature), Feature can be disabled and completely not visible to the customer.

·      Features should be enabled / disabled per customer in the admin portal (Django admin).

·      Features configuration should be aggregated into packages. Enabling package – enables all the features under the package, disabling the features will disable all the feature (according to the feature disablement configuration – visible/not-visible). We should have 3 pacakge definitions:

o   Basic – enables for all

o   Gold

o   Platinum

·      Features enable/disable and packages upgrade and downgrade should be monitored as system KPI

·      Package upgrade process –

o   Phase 1 – should be done manually via request to the system admin, updated in Django admin.

o   Phase 2 – should be done via the setting form, the users should choose which package to upgrade, and the system should enable this automatically and update the package tracking.

Same goes with package downgrade.

·      Option 1 – Billing and sub-scription section within settings (see Figma)

·      Option 2 – Pressing greyed out function, which should take you to the same billing and subscription section

·      Packages should be connected to the user subscription billing process and update the next billing cycle (there’s no package pro rating calculation in system).

·      Except for packages there are features that should have enabled / disabled flag in order to allow system customization (even if they are included in all packages). The behavior should be exactly the same as package based features, not difference in the implementation process, only sematic package definition (example – lead and project management).
