1. Proposal and contract should have separate templates.

  2. Templates should be editable per office (in settings, save as template).

  3. Proposal and contract are built based on blocks.

  4. Each block can be displayed or not displayed (implemented today).

  5. Each block title, including the existing one should be editable.

  6. Block ordering should be available, moving them before or after the current blocks.

  7. Blocks definition:

    1. Adding new blocks should be optional at the end of each block through a plus button (see Figma).

    2. Block position should be defined by the user with 3 options - alignment to left, right and center (icon based, similar to word).

    3. New block can be one of the following options:

      1. Title + Free text.

      2. Title + bulleted text.

      3. Title + table. Table should be predefined with number for columns and rows, adding rows at the end should be available.

        1. Future - columns type should be defined as number or text in order to allow editing validation.

      4. Image.

      5. Signature plus date section.

      6. Initial signature with no date.

      7. Appendix document - embedding full pages at the end of the proposal and contract. Should support Image, PDF and Word formats.

    4. Existing table blocks should allow column removal.

    5. Existing tables blocks duration column scale should be editable (days/weeks/months).

    6. We still have a gap for milestones in a project with multiple project type. As discussed we should have additional level of project type in addition to the milestone.

  8. Proposal and contract status should be with the following states - "In Review", "Approved", "Under Revision", "Cancel"

  9. Change buttons name in both proposal and contract (opposite of existing implementation):

    1. Generate - creating the document.

    2. Submit - saving the document to the lead.

  10. Lead kanban Proposal and contract status should say “Proposal” and/or “Contract”, and not just the indication + tooltip.

  11. Admin should be able to cancel proposal and/or contract.

  12. Date format should be aligned to US format - MM/DD/YYYY.

    1. Future - configurable in settings.

  13. Milestone end date should start from the start date (not as a limitation, but as focus).

  14. Future - Settings should include workweek definition, by selection from the following options:

    1. Sunday-Saturday.

    2. Monday-Friday.

    3. Sunday-Friday.

    4. Monday-Saturday.

  15. Future - Milestones duration should be auto calculated from the lead milestone definition, based on End date minus start date. The duration should be auto assigned in days.
