RBAC Master Matrix

Roles & Permissions Hierarchy

This document describes the complete EZBuild.AI Role‑Based Access Control (RBAC) model. Roles define access to modules, actions, data visibility, and approval authority. The permission hierarchy follows a strict top‑down model:

  1. System Admin – Full access to all system resources, internal tools, overrides, and support functions.

  1. GCC – Company Owner with full company-level access including all modules, billing, templates, and role assignments.

  1. GCC Admin – Operations Administrator with broad access excluding billing, role hierarchy changes, and system‑level settings.

  1. Project Manager – Manages execution of assigned projects. Cannot view items outside their assignment.

  1. Sales – Manages leads, estimates, and conversions. Project visibility limited to assigned or created items.

  1. Subcontractor – Limited access to assigned project scopes, AP invoice submission, and compliance documents.

  1. Customer – Read-only access to their own project(s), invoices, and communication.

Role Hierarchy & Visibility Model
System Admin → GCC → GCC Admin → PM → Sales → Subcontractor → Customer

Visibility Levels:

·      View All: User can see all records across the organization.

·      View Assigned: User can only see records assigned directly to them (project, lead, task, invoice, etc.).

·      No Access: User cannot see or interact with the module.

Permission Visibility Types

·      Access – User can perform the action.

·      No Access – User cannot perform the action.

·      View All – User can view all records.

·      View Assigned – User sees only items assigned to them.
